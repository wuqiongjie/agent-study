# 03 · Demo 阶梯

按顺序做，每一步都必须「能跑起来、能演示、能截图」。跳过任何一步都会导致后面看不懂。

---

## Demo 0 · 手写最小 Agent（必做）✅ 已完成 2026-10-21

- **形态**：Node CLI，**不使用任何框架**
- **工具**：`get_weather(city)`（可先用假数据返回）
- **任务**：体验一次完整的「模型要求调工具 → 我执行 → 回传 → 模型总结」
- **产出**：命令行打印每一步的 `messages` 数组
- **验收**：
  - [ ] 报文流转看得懂
  - [ ] 能解释 `tool_choice: 'auto'` 与 `'none'` 的区别
  - [ ] 设置了 `maxSteps` 护栏
- **预计**：0.5 天

---

## Demo 1 · Next.js 流式聊天界面 🟡 进行中（2026-10-21 开始）

- **形态**：Next.js App Router + Vercel AI SDK
- **功能**：
  - `useChat` 流式打字机
  - 工具调用过程可视化（「正在调用 getWeather…」折叠卡片）
  - 消息列表持久化
- **关键 API**：`streamText` / `maxSteps` / `tool` / `useChat`
- **产出**：一个可以发给朋友看的网页
- **验收**：
  - [ ] 首字节延迟 < 1s
  - [ ] 网络断开后前端不崩，能提示错误
  - [ ] 刷新页面后的行为符合预期（持久化或清空，二选一且明确）
- **预计**：1 天

## Demo 2 · ReAct 调研助手

- **工具**：`web_search(query)` / `fetch_url(url)` / `write_file(path, content)`
- **任务**：「调研 XX 技术并输出一份 Markdown 报告」
- **首次体验**：Agent 自主规划、连续调 5~10 次工具
- **验收**：
  - [ ] 报告里的事实能溯源到抓取的原文
  - [ ] 记录了该任务的总 token 与耗时
  - [ ] 出现过的失败模式已写进 `notes/`（如：反复搜同一个词、抓取失败不重试）
- **难点**：HTML → 正文提取（这一步会教你为什么工具结果必须**精简**后再回传模型）
- **预计**：1~2 天

---

## Demo 3 · 人在回路（Human-in-the-loop）

- **场景**：发邮件、写数据库、删文件等不可逆操作
- **机制**：工具执行前中断 → 前端弹「允许 / 拒绝 / 修改参数」→ 结果回传继续
- **实现**：LangGraph.js 的 `interrupt`，或 Vercel AI SDK 的 `requiresApproval`
- **验收**：
  - [ ] 拒绝后 Agent 能给出合理替代方案，而不是直接崩掉
  - [ ] 用户修改参数后 Agent 用的是修改后的值
  - [ ] 中断状态刷新页面后不丢失（持久化）
- **意义**：这是 Agent 产品的刚需，也是前端最能做出差异的地方
- **预计**：1~2 天

---

## Demo 4 · Generative UI / Artifact

- **形态**：工具结果不返回文本，而是直接渲染成一个 React 组件
- **例子**：
  - 查询结果 → 渲染成图表 / 表格卡片
  - 「帮我做个落地页」 → 右侧画布实时渲染 HTML 预览
- **关键 API**：`streamUI` / RSC / 组件注册表
- **验收**：
  - [ ] 组件随流式输出渐进呈现，不是等全部完成
  - [ ] 渲染出错有兜底 UI，不会白屏
- **说明**：这就是 Claude Artifacts、Vercel v0 的形态
- **预计**：2 天

---

## Demo 5 · 多 Agent + MCP

- **结构**：planner（规划） / researcher（检索） / coder（写代码） 子 Agent 协作
- **工具**：接入 MCP 现成工具集（文件系统、GitHub、浏览器）
- **验收**：
  - [ ] 子 Agent 之间只传必要信息，不共享完整上下文
  - [ ] 单个子 Agent 失败不会导致整体崩溃
  - [ ] 有完整的 trace 可以复盘每一步
- **产出**：到这步已经能看懂市面上绝大多数 Agent 产品
- **预计**：3 天+
